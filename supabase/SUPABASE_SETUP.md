# Supabase setup (Free plan)
1. Create a project at supabase.com (Free plan). Note the Project URL and anon key — put them in `.env` as `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`. **Never put the privileged Supabase service key in the frontend or repo.**
2. Dashboard > SQL Editor: run `supabase/storage-policies.sql`. It creates two public buckets:
   - `reform-media` (admin content): `gallery/`, `events/`, `team/`, `blog/`, `recognition/`, `legacy/` images and `docs/` PDFs. 10 MB bucket limit; image + PDF mime types. Admin-only insert/update/delete via the `reform_admin` JWT claim.
   - `reform-submissions` (public uploads): `submissions/` (member artwork) and `w2b/` (Waste to Best entries) only. 5 MB bucket limit; image mime types only (`image/jpeg`, `image/png`, `image/webp`). Public read; anon insert only on `submissions/` and `w2b/` (WebP/JPG/PNG names, 5 MB metadata backstop); admin-only insert/update/delete elsewhere via the `reform_admin` JWT claim, which is how the coordinator deletes orphaned public submissions.
   Size split: public images are capped at 5 MB (5 MB bucket limit on `reform-submissions` + anon insert policy metadata check + client validation in `validateFile.js`), `docs/` PDFs at 10 MB (10 MB bucket limit on `reform-media` + client validation). Set the bucket names in `.env` as `VITE_SUPABASE_BUCKET=reform-media` and `VITE_SUPABASE_SUBMISSIONS_BUCKET=reform-submissions` (both have these defaults in code, so they work blank too).
3. Enable Firebase third-party auth: Dashboard > Authentication > Third-party > Firebase, enter the Firebase project ID. Supabase then accepts Firebase ID tokens; `uploadService` attaches the token for admin uploads (and as the `Authorization` header on the XHR upload used for progress reporting).
4. Run `node scripts/set-admin-claims.js` after creating admins so they get `{role:'authenticated', reform_admin:true}`.
5. Free-tier limits: 1 GB storage, bandwidth cap, project pauses after inactivity. If third-party auth is not enabled, admin deletions fall back to marking `deleted: true` in Firestore and purging manually in the Supabase dashboard.
6. Backup: Dashboard > Storage > bucket > list/download, or Supabase CLI `supabase storage ls`. Restore by re-uploading the same paths.
7. Orphan cleanup: the coordinator-only Orphan Cleanup page (`/admin/orphans`) lists files in `reform-submissions` (`submissions/`, `w2b/`) and `reform-media` (`gallery/`, `events/`, `team/`, `blog/`, `recognition/`, `legacy/`, `docs/`) that no Firestore document references, and deletes them with confirmation + audit log. In demo mode it shows the same logic against simulated rows.
